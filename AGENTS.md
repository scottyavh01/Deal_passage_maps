# Guidance for agents working on passage summaries

## Default: create a new version

Treat a request to change, regenerate or add passage summaries as a request for a **new version**, even if the user says only “move this box” or “put (planned) next to this time”. The user does not need to repeat the versioning or validation instructions. An explicit request to update a particular existing file in place takes precedence; a request only to change repository documentation does not require a new summary version.

1. Find the newest existing root-level folder matching `summaries_YYYYMMDD_HHMMSS`, using descending timestamp order. Read its `README.md` and `create.py`, and inspect the relevant inputs and current outputs. Treat the actual working-tree files, including any uncommitted edits, as potential user work: do not discard, reset or overwrite them. Unless the user chooses a different baseline, copy the latest folder's current generator and README **as they exist**, including uncommitted changes. If their intent is genuinely unclear, ask before modifying anything.
2. Create a **new, unique** timestamped sibling folder directly under the repository root. Never overwrite or reuse an existing folder; if the timestamp collides, choose another unique valid timestamp. Copy the baseline's `create.py`, `README.md`, and any other files needed to reproduce that version into the new folder. The current scripts resolve the source maps through their parent directory, so preserve that relationship.
3. Make the requested changes only in the new folder. Do not alter existing versions, original maps or passage-plan inputs unless the user explicitly authorizes that change. **Do not run the baseline's generator**: it overwrites its own output PDFs and PNGs. Generate in the new folder and leave all existing files and uncommitted changes intact.
4. Preserve the map's aspect ratio and its embedded passage line. Generate both single-page PDFs and matching, high-resolution phone-friendly PNGs unless the user explicitly asks for a different deliverable. Inspect **both** generated pages and both image exports after changing the generator; check that output is complete and legible, page content matches, there is no clipping or overlapping text, and boxes do not obscure route lines, header or map edges. Where practical inspect on a phone or at phone scale. Check page count and dimensions, and explicitly report any check you could not perform.
5. Update the **new version's** README with the changes, how to reproduce them, relevant inputs and page dimensions, calculations, sources and any limitations. Update the root README only if a repository-wide instruction or current-output fact has become inaccurate; keep the general iteration guidance there accurate. Link the new deliverables in the response.

Generated PDFs and PNGs may change as a pair even when only one page was edited; do not assume they are interchangeable without checking.

## Creation workflow

### Inputs and outputs

The current generator is in the newest version folder. It expects `St_Kilda_to_Deal_with_passage.png` and `Deal_to_Welshpool_with_passage.png` in the repository root, one directory above the script. The red passage lines are embedded in those images, not generated by the script. The original passage-plan PDF is a reference for the journey and tide screenshots; the generator does **not** read the PDF or retrieve tides automatically. Values, dates and locations are entered in the script. The other original PNGs and annotated JPEG were used in earlier layout iterations.

Each version normally contains `create.py`, its `README.md`, and a PDF and PNG for each passage. The version README contains the source details and any exceptions that apply to its outputs.

### Regenerate or iterate

Python 3, [ReportLab](https://pypi.org/project/reportlab/) and [PyMuPDF](https://pypi.org/project/PyMuPDF/) are required; dependencies are not pinned. In the **newly created version folder**:

```bash
python -m pip install reportlab pymupdf
python create.py ocean
```

**Running the current script overwrites that folder's two passage PDFs and two PNGs.** Create the new timestamped folder and copy the baseline into it first, as described above; never run the existing baseline merely to inspect or reproduce it. The current script works offline once its dependencies are installed; refreshing predictions requires consulting sources separately. The legacy `light` style has not been validated for the latest changes.

ReportLab draws each page and overlays the information boxes; PyMuPDF renders the PDF page to a lossless PNG at 2× the page's point dimensions. In `create.py`, `create()` calculates each page's height from its input map and any additional margins, `panel()` and `text()` draw boxes and text, and `rows()` and `rip_rows()` format tide tables. The page-building blocks near the end contain the values and placements. PDF coordinates start at the **bottom left**; several boxes use `saveState()`, `translate()` and `scale()`, so their coordinates are local to those transformations. Recheck placement whenever map dimensions, text or font size change.

### Check before sharing

1. Inspect **both PNGs** at full resolution and, where practical, on a phone or at phone scale: text and all events should be legible, complete and inside their boxes, with no clipping or overlap with the header, map edge or passage line. Verify the maps retain their original proportions.
2. Confirm each PDF has one page and matches its PNG. Test print scaling if a printed copy is needed; report any checks that could not be performed.
3. Recheck dates, passage calculations, tide stations, event types, current direction and source time zones. Do not infer missing predictions or equate high/low water with slack current. Record uncertain or unavailable information explicitly in the version README and, where relevant, on the sheet.
4. Preserve existing files and source material. Review the resulting version's README so another agent can trace values and reproduce the outputs.

## Safety and data integrity

These are planning summaries, not navigational charts. Preserve important context, source references and unresolved caveats. For any changes to tides or current predictions, verify station, event type, dates, time zone and source; distinguish water-height high/low from tidal-current slack, and do not infer missing navigation-critical values. Flag unavailable or unverified information rather than inventing it. Confirm assumptions and arithmetic for passage times and arrival dates. Do not describe a highlighted planned time as a guarantee of actual slack.

Keep the exact original passage images and source documents unchanged unless expressly requested. The repository is intended for private sharing and includes personal and itinerary information; avoid exposing it unnecessarily.
